# T-M1-04 — Sort the first trial feedback into fixes and roadmap items

## Why

Friends who tried 0.1.0 found the rough edges; each note should end up somewhere — a fix card, a roadmap item, or
"won't do" with the reason — so nothing is lost and nothing is built without the owner's Go.

## What to do

1. Collect the notes (issues, messages the owner forwards) in `docs/plan/feedback/v0.1.0.md`: one row per note — what
   happened, who saw it, which version, decision (fix now · roadmap · won't do) and why
2. Bugs that block installing or the first card: a card in the next milestone, written with `/saf-plan`
3. Ideas: a line in `ROADMAP.md`; the owner decides when
4. No names or contact details of the people who gave feedback in the repository

## Out of scope

- Fixing the bugs (their own cards)

## Done when

- `npm run docs:check`
- `npm run check-secrets`
