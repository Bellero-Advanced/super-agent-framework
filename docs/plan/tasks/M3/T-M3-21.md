# T-M3-21 — Setup messages say what happened

## Why

Proposed card D, part 2 (setup and upgrade messages). Review notes:

- 27/N3 — a `[]`, `null` or string settings root is "not valid JSON" in the warning and the dry-run line, though it is
  valid JSON; the `settings.json` warning does not name its archive path (`report.archived` does)
- 22/N6 — the dry run prints no archive target for `replace-edited` files, so the `.1` / `.2` suffix of an older
  archive shows only after the real run
- 18/1 — a minified one-line `package.json` is re-expanded to 2-space indent when a script is added

[setup-rerun rules 35–36](../../../specs/setup-rerun.md#messages-that-say-what-happened-generatemjs) ·
[upgrade-scripts rule 14](../../../specs/upgrade-scripts.md#2-rules).

## What to do

- `planSettings`: two reasons for an unreadable file — parse failure → "is not valid JSON", valid non-object root →
  "is not a JSON object"; both settings warnings name their archive path; the dry-run line uses the same reason words
  (T-M2-30's `archivedWhy` / `localArchivedWhy` carry them)
- `planLines`: a `replace-edited` line ends with ` → <to>`
- `mergeScriptsText`: no indented line in the original → stringify without indentation (keep BOM, line endings and
  trailing newline as today)
- `test/unit/setup-messages.test.mjs`: RERUN-AC-20 and UPG-AC-08 (ids in the names); both must fail on the code before
  this card
- `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then restore
  `examples/todo-api/.claude` and `examples/todo-api/package.json`
