# T-M3-20 — Strict CLI arguments and a true fallback reason

## Why

Proposed card D of [M3 "Carried to M3"](../../milestones/M3.md#carried-to-m3), part 1 (CLI strictness). Review notes:

- 12/7 · 13/12 — `choices --group 2 --foo`, `--lang=th`, `choices foo --group 2` exit 0 and ignore the extra input; the
  `config` case ignores everything after it and crashes with a stack trace on invalid JSON (`JSON.parse` unguarded)
- 12/5 — a schema-invalid but valid-JSON config still gives its `chatLanguage`; the spec now says that is intended
  (edge cases) — this card adds the test
- 14/N3 — `planVerifyRun` (`task.mjs`) says "no stack.commands.testFiles command" also when the command exists but lacks
  the `{files}` placeholder

[setup-choices rules 15, 26 and §4](../../../specs/setup-choices.md#the-cli-node-toolssafbinsafmjs-choices) ·
[test-mode rule 13](../../../specs/test-mode.md#card-verify-taskverify-card).

## What to do

- `saf.mjs` `choices`: parse every argument; allowed are `--group <g>`, `--not-asked`, `--lang <l>`, each at most once;
  anything else (including `=` forms and stray words) → the existing usage line, exit 2
- `saf.mjs` `config`: exactly `--check`, else a usage line and exit 2; read the file guarded: not valid JSON or a
  non-object root → `✗ saf.config.json is not valid JSON` / `is not a JSON object`, exit 1, no stack trace
- `task.mjs` `planVerifyRun`: three fallback texts — no `testFiles` command · `testFiles` has no `{files}` placeholder ·
  no targeted test files (read the placeholder from `testmode.mjs`'s export; do not retype it)
- `test/unit/cli-strict.test.mjs`: SETUP-AC-12, SETUP-AC-13, TMODE-AC-20 (ids in the names); AC-12 and AC-20 must fail
  on the code before this card
- `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then restore
  `examples/todo-api/.claude` and `examples/todo-api/package.json`

## Out of scope

- Other subcommands' argument parsing (`task …` already validates) · `FIELD_MAX` headroom (13/13, dropped — the data
  test already fails on the next over-long field)
