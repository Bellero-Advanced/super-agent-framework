# T-M3-11 — Release workflow with npm trusted publishing

## Why

The npm publish runs in CI on a tag the engine created, authenticated by GitHub OIDC — no npm token stored anywhere
(npm now restricts long-lived and 2FA-bypass tokens). The workflow re-checks the guards itself, so a tag pushed by
hand or a kill switch turned off after tagging still stops it. **Security-relevant:** build and review with the
`security-review` skill. [Spec rules 15–21](../../../specs/auto-release.md#release-workflow-this-repository-t-m3-11).

## What to do

- `.github/workflows/release.yml` per rules 15–18: `on: push: tags: ["v*"]`; top-level `permissions: contents: read`;
  one job `publish` with `environment: npm`, `permissions: contents: write, id-token: write`; checkout with full
  history; setup-node pinned to a version npm trusted publishing supports and npm upgraded to its minimum CLI version
  (look both up in npm's trusted-publishing docs at build time; put the link in a comment); `node scripts/release-check.mjs guards ${{ github.ref_name }}`
  (with `GH_TOKEN: ${{ github.token }}`); publish `super-agent-framework` then wait, then `create-saf`, each skipped
  when that version is on npm, each preceded by the kill-switch check; `gh release create` with the CHANGELOG section
  (skipped when it exists); `release-check npm` and `release`. No `secrets.*` npm token, no `NODE_AUTH_TOKEN`
- `scripts/release-check.mjs`: new checks `guards <tag>` (rule 17, reusing `nextVersion`, `readChangelog`,
  `readReleaseLog` from `tools/saf/lib/release.mjs`; the OS list read from `ci.yml`'s matrix) and `workflow` (rule 19,
  static, no network); outside calls behind an injectable runner so tests stay offline; existing checks unchanged
- `docs/releasing.md` (rules 20–21): for maintainers of any SAF project — the setting and kill switch, the guards,
  dry run → prepare → tag, what their own tag workflow must do (this one as the example), npm trusted-publishing
  setup in steps, and what SAF cannot do; `docs/INDEX.md`: point the release row at it
- this repo: `saf.config.json` `policies.release`: `auto: "on"`, packages `.` and `packages/create-saf`, version file
  `kit/tools-saf/VERSION` (D-015; nothing is released until M3 is closed and the owner setup is done)
- `test/unit/release-check.test.mjs`: one test per scenario id in its name; AC-08 mutates a copy of `release.yml`
  (token reference, missing `id-token: write`, branch trigger, missing guards step)

## Out of scope

- engine release steps (T-M3-09, T-M3-10) · the owner's npmjs.com and GitHub setup (M3 gate `owner-setup`) · the
  first real release (after M3 closes)
