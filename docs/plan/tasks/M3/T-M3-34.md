# T-M3-34 — task:merge uses the always-allowed globs of main and of the branch

## Why

Friction F-011 (`command-failed`, self-fix #1 of 3 the owner approved for M3, D-017): T-M3-33 added globs to
`workflow.alwaysAllowed` and `task:merge` refused it with "changed after verification", because the merge check reads
only the main folder's (old) list; the workaround was copying the lane's `saf.config.json` to main by hand — the
second time after F-005. [Spec rules 1–6](../../../specs/merge-allowed.md#2-rules). Code card, role effort: medium.
Runs first among the open M3 cards: T-M3-16 · T-M3-18 · T-M3-22 · T-M3-23 depend on it (T-M3-18 also shares
`task.mjs`).

## What to do

- Write `test/unit/merge-allowed.test.mjs` first and see it fail on the start commit (`tdd` skill): MALLOW-AC-01 …
  -03 (ids in the test names), lanes in temporary repositories with `planRepo` + `task.startCard(…, { worktree: true })`
  as in `test/unit/task.test.mjs`; the lane verifies with `loadConfig(lane)` (its new list), the main folder's ctx
  keeps the config from before the lane; `task.mergeCard(ctx, id, { checks: [] })`
- `kit/tools-saf/lib/task.mjs` `precheck`: read `CONFIG_FILE` from `refs/heads/<branch>` with `showFile`; take its
  `workflow.alwaysAllowed` strings (anything unreadable → none, rule 5); use them only when the branch config is the
  verified one (unchanged since the merge base, or in `v.files.changed` with the same hash — rule 4); skip a file when
  it matches main's list, the card file, or one of those globs — but never skip `CONFIG_FILE` through a branch-only
  glob (rule 3). Refusal text and exit codes unchanged
- `docs/card-lifecycle.md` "Lanes", the `task:merge` bullet: one sentence — the check skips files allowed by the main
  folder's `workflow.alwaysAllowed` or the branch's, so a card that adds a glob merges in one step
- `npm run saf:refresh` (engine copies are always allowed)

## Out of scope

- Built-in always-allowed paths added in `plan.mjs` by the branch's engine (F-005) · `task:verify` / `task:start` /
  `task:next` reading other lists · closing F-011 as fixed (T-M3-08's auto-close has not landed — the main session
  runs `npm run task:friction -- close F-011 fixed T-M3-34` after the merge)
