# T-M3-10 — task:release --prepare and --tag

## Why

The two steps that change the outside world: a release commit pushed to `main`, then — only when CI is green on that
exact commit — a tag. Each runs only when its guards hold, never forces, never deletes. **Security-relevant:** build
and review with the `security-review` skill. [Spec rules 10–14](../../../specs/auto-release.md#--prepare-and---tag).

## What to do

- `release.mjs`: `prepareRelease(ctx, mid)` (rule 10: bump every released package, inter-package dependencies and
  version files; move `## Unreleased`; append the release-log line; commit exactly those files; plain `git push`; a
  rejected push keeps the commit and exits 1) and `tagRelease(ctx, mid)` (rule 11: subject check, guards with
  `step: "tag"`, annotated tag with the CHANGELOG section, push only `refs/tags/v<version>`); print each git command
  before running it (rule 13); keep every outside call behind the injected runner
- `bin/saf.mjs`: wire `--prepare` and `--tag` (refuse both together; refuse in a lane)
- `/saf` templates (en, th) + `generate.mjs` (`cmd.taskRelease`, the `policies.release.auto` flag): rule 14 — when
  `auto` is on and the owner has closed a milestone: dry run → `--prepare` → wait for CI → `--tag` → report; when off:
  releases need the owner's order
- `test/unit/release-run.test.mjs`: bare-remote fixtures, fake CI runner (one skipped job, then all green); one test
  per scenario id in its name; AC-07 scans `release.mjs` for the forbidden commands of rule 12
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then
  `git checkout -- examples/todo-api/.claude`

## Out of scope

- publishing (the workflow, T-M3-11) · writing CHANGELOG entries (cards do; T-M3-12 catches up M2 and M3)
