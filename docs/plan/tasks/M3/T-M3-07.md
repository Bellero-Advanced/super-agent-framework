# T-M3-07 — Friction triage: report section, designer brief, card drafts

## Why

A log nobody reads changes nothing. At milestone end the report must put open friction in front of the designer,
grouped so recurring problems stand out, and hand over drafts that only need `touch` and commands filled in — without
the engine ever writing a plan file by itself. [Spec rules 15–17](../../../specs/friction-log.md#triage-at-milestone-end-t-m3-07).

## What to do

- `friction.mjs`: `FRICTION_LIMITS` (`recurring`), `SELF_FIX_KINDS` (`command-failed`, `doc-drift` — D-017),
  `groupFriction(entries)` → groups by kind + area with count, ids, newest evidence, recurring flag;
  `renderDrafts(plan)` per rule 16 (target milestone: the active one, else the next planned one; `T-M<n>-??` ids)
- `report.mjs` + `text.mjs` (en, th): the "Friction" section after the gates (rule 15); "no friction recorded" when
  the file is missing or has no open/carded entry
- `bin/saf.mjs`: `task friction draft` prints the drafts to stdout, writes nothing, exit 0 (also with no drafts, with
  one line saying so)
- `docs/card-lifecycle.md`: milestone end — read the Friction section, run `task:friction draft`, the designer turns
  drafts into cards (Go needed) or closes entries `dropped` with a reason
- `test/unit/friction-triage.test.mjs`: one test per scenario id in its name; AC-09 asserts the worktree is unchanged
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then
  `git checkout -- examples/todo-api/.claude`

## Out of scope

- the `self_fix` card field, its plan check and auto-close (T-M3-08) · the HTML report (T-M2-05 renders what it
  renders)
