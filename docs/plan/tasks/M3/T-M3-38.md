# T-M3-38 — task:culprit interrupt during install on Node 20

## Why

Friction F-017: CI run 45560880247 failed `TMODE-AC-17 SIGINT/SIGTERM during the install step` on Node 20 (ubuntu, macOS,
windows) with `✗ … exited 1 … cannot judge this commit` instead of exit 130 / 143. Reproduced locally on Node v20.17.0
(`~/.nvm/versions/node/v20.17.0/bin`); Node 22 passes. Cause (proven): `settle()` in `culprit.mjs` waits one
`setImmediate`; on Node 20 a signal that arrived while `runSync` blocked the loop is not delivered by then, so the
install failure is reported before the signal handler runs. A one-line trial (`setImmediate(() => setTimeout(resolve, 0))`)
made all four TMODE-AC-17 tests pass on 20.17.0. [Spec rule on interrupts](../../../specs/test-mode.md).

## What to do

- Test first: add an in-process test to `test/unit/culprit-robust.test.mjs` named `TMODE-AC-17 …` where
  `ctx.runSync` sends the process its own SIGINT and returns 1; `findCulprit` must return kind `interrupted`, exit 130.
  It must fail on Node 20.17.0 before the fix (run it with that binary first on PATH) — if it cannot be made to fail
  there, say so and keep the existing install tests as the proof
- `kit/tools-saf/lib/culprit.mjs`: make `settle` also pass one timer turn (`setImmediate` then `setTimeout 0`); nothing else
- `npm run saf:refresh` (copies in `tools/saf` and the example); never edit `tools/saf` by hand
