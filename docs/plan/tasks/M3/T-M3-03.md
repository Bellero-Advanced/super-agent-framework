# T-M3-03 — Effort setting, variant agent files, docs:check

## Why

D-016: effort by card size instead of one effort per role. Claude Code fixes a subagent's effort in its agent file,
so a different effort means a second file per role. This card adds the setting, the table, the resolution and the
files; T-M3-04 makes `task:start` name the agent. [Spec rules 1–10](../../../specs/effort-by-size.md#2-rules).

## What to do

- `config.mjs`: `EFFORT_BY_SIZE` with the values of D-016; `models.effort` default `fixed`; `LOCAL_KEYS` gains
  `models.effort`; the resolved config records `models.effortSource` (follow `workflow.testModeSource`); a custom
  role named like a variant (`<role>-<effort>` of an enabled role) is a config error
- schema: `models.effort` enum `fixed` · `by-size`
- new `kit/tools-saf/lib/effort.mjs`: `cardEffort(config, card)` → `{ effort, agent, mode, source, warning? }` (rules
  3–4, 10; a card without size counts as M) and `variantAgents(config)` → `[{ role, effort, name }]` (rule 6, using
  `roleTable` so overrides apply)
- `generate.mjs`: `plannedFiles` adds the variant files (rule 7: same template, name, effort, the description prefix);
  `refreshKitFiles` writes and retires variant agent files only (rule 8) — base agent files stay setup-only
- `docs.mjs`: accept valid variants, report the mismatches of rule 9
- `choices.mjs`: `models.effort` in `NOT_ASKED` (en + th one-liners) so SETUP-AC-01 stays green until T-M3-05 asks it
- `test/unit/effort-by-size.test.mjs`: one test per scenario id in its name; AC-03 in a temp project with a manifest
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then
  `git checkout -- examples/todo-api/.claude` (this repo stays `fixed` until T-M3-06, so no agent file changes here)

## Out of scope

- `task:start` output, evidence, summary, templates, report (T-M3-04) · the setup question (T-M3-05) · switching this
  repo (T-M3-06)
