# T-M3-09 — task:release dry run, guards, kill switch

## Why

D-015 lets SAF release itself only behind guards. The guards come first, as a read-only dry run that anyone can run
at any time and that tests can drive with fake git, registry and `gh` answers. **Security-relevant:** build and
review with the `security-review` skill. [Spec rules 1–9](../../../specs/auto-release.md#2-rules).

## What to do

- schema + `config.mjs` defaults: `policies.release` `{ auto: off|on (default off), packages (default ["."]),
  versionFiles (default []), ciWorkflow (default "ci.yml") }`, no extra properties; never in `LOCAL_KEYS`;
  `choices.mjs`: `NOT_ASKED` lines (en + th) — `auto` says it lets SAF push, tag and trigger publishing when every
  guard holds, off by default
- new `kit/tools-saf/lib/release.mjs` (no dependency; every outside call goes through an injected `run(cmd, args)`
  so tests never touch the network): `readChangelog(text)` → `{ unreleased: { <sub-section>: [lines] }, releases:
  [version] }`, `nextVersion(current, changelog)` → the next version or `null` (rule 7; T-M3-12 and `release-check`
  call exactly these signatures), `RELEASE_LOG`
  (`docs/plan/releases.md`) and `readReleaseLog`, `releaseGuards(ctx, mid, { step })` → `[{ id, ok, reason }]` for
  G-switch, G-branch, G-milestone, G-version and, for `step: "tag"`, G-ci and G-log (rules 4–9), and
  `planRelease` → the version and the actions each step would take
- `bin/saf.mjs`: `task release <M>` prints every guard and the plan, writes nothing, exit 0 / 1 / 2;
  `--prepare` and `--tag` print "not built yet (T-M3-10)" and exit 2 until the next card
- `config.mjs` `ENGINE_SCRIPTS` `task:release`; `package.json` script; example `package.json` through the example
  upgrade
- `test/unit/release-guards.test.mjs`: git fixtures with a bare remote in temp folders, fake registry and `gh`
  runners; one test per scenario id in its name; AC-04 asserts the worktree and the remote are byte-identical
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then
  `git checkout -- examples/todo-api/.claude`

## Out of scope

- writing, committing, pushing, tagging (T-M3-10) · the workflow and `release-check` (T-M3-11) · turning it on here
