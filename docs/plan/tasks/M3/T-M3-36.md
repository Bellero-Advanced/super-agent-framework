# T-M3-36 — Setup and user-doc wording for sizes M and L

## Why

After T-M3-35 the engine has sizes M and L and a hard stop, but the setup explanations, the setup questions and the
user docs still talk about S cards, "a warning, not a failure", and rigor making cards larger or smaller. Every
sentence must say what the code now does. [Spec rules 17–18](../../../specs/card-sizes.md#wording-in-setup-and-the-user-docs-t-m3-36).
Role effort: high (text for users — the M2 text cards built at medium bounced at round 1).

## What to do

- `choices.mjs` (en and th, every changed field within `FIELD_MAX`, no digits, no model ids): the `project-rigor`
  options drop "larger cards" / "smaller cards" (light, strict; th likewise); `size-caps` — caps for M and L cards,
  the same table for every rigor, verify warns above a cap and fails above twice it; `LABELS.*.reviewWords["m-cards"]`
  and `NOT_ASKED["workflow.review"]` — M and L cards each get a review, legacy S cards together at the gate;
  `NOT_ASKED["workflow.selfFix"]` — size M (keep the th phrase
  `engine ไม่ยอมรับอย่างอื่น เรื่องที่ใหญ่กว่านี้จึงยังต้องรอเจ้าของ`); the `effort` options, `NOT_ASKED["models.effort"]`
  and its `MACHINE_SWITCHES` line — "M cards" / "L cards" where they say small / large
- `questions.md`: rigor table without the size columns (one sentence: caps come from the size table, the same for
  every rigor); the `workflow.sizes · workflow.testCaps` row says `{ M, L }`, default "the size table"; the effort
  paragraph says M cards · `SKILL.md` line 66: the derived values of a rigor are the M / L caps, review and merge checks
- `/saf` templates (en, th) and `.claude/commands/saf.md`: the review row's m-cards text (M and L cards; legacy S at
  the gate), the self-fix section (one size M card; L never a self-fix card); then `npm run saf:refresh`
- CLAUDE templates (en, th): the m-cards Definition-of-done review line (only rendered with `workflow.review: m-cards`)
- `docs/card-lifecycle.md`: step 2 `size <M|L>` and the legacy note; step 4 — warning above the cap, hard stop above
  twice it (no command runs, exit 1, the designer splits), legacy S counts as M; step 5 review line; the Card format
  example `size: M` with a comment pointing to `SIZE_CAPS` (no numbers copied); the Self-fix conditions (size M) and
  "size L" in what waits
- `docs/config-reference.md`: `rigor` row (review and merge checks only), `sizes · testCaps` row (`{ M, L }`, the table
  in `lib/config.mjs`, the hard stop, the old `{ S, M }` shape ignored with a warning), `review` row (m-cards wording),
  `selfFix` row (size M) · `docs/setup-questions.md` item "card size caps": M / L
- `test/unit/card-sizes-text.test.mjs`: SIZE-AC-10 and SIZE-AC-11, each sentence checked in its own field / section
