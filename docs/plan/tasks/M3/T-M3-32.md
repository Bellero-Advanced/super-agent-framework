# T-M3-32 — spec:matrix --check counts a card only where it is built

## Why

Friction F-008 (`command-failed`, carded under D-017): `spec:matrix --check` in a lane fails while another lane's
started card has its tests only on its own branch. T-M3-28 and T-M3-29 deadlocked and were freed only by
`task:abandon` and a restart. [Spec rules 1–10](../../../specs/matrix-scope.md#2-rules). This card runs **alone**:
until it lands, any second lane card with scenarios can hit the same deadlock.

## What to do

- `matrix.mjs`: `buildMatrix` also records each card's evidence lane (new optional input `lane: (id) => …`, the cards
  in a row carry `lane`); `blockingGaps(m, here)` — `here` = `{ laneCard: <id> | null }`; without `here` the old
  behaviour (every non-`todo` card counts, the existing test in `test/unit/checks.test.mjs` stays green); a helper for
  the gaps skipped because their started cards are built elsewhere (rule 7); `renderMatrix(m, here)` and
  `summarize(m, here)` use the same selection and texts (`✗ gap (started in another folder)`,
  ` · started in another folder <n>`)
- `bin/saf.mjs` `spec-matrix`: compute `here` once with `laneFolder(root, plan)` (already exported from `task.mjs`);
  when it throws, print `lane not recognised (<reason>) — checking every started card` on stderr and use no `here`
  (rule 6); pass `here` to `blockingGaps`, `renderMatrix`, `summarize` and the GitHub step summary; exit codes and
  `--complete` unchanged
- `docs/card-lifecycle.md` "Specs and scenarios": one sentence — a card still being built counts only in its own
  folder (its lane, or the main folder for main-folder cards); finished cards count everywhere
- `test/unit/matrix-scope.test.mjs`: MSCOPE-AC-01 … -07 (ids in the test names); lanes in temporary repositories with
  `task.startCard(…, { worktree: true })` as in `test/unit/task.test.mjs`, run the CLI with `process.execPath` and an
  argument array (Windows-safe); AC-04 on a built matrix
- `npm run saf:refresh` (engine copies are always allowed)

## Out of scope

- `task:next --parallel` counting by the current role lane (review note D1) · reading other branches for tests ·
  the CLAUDE templates' one-line comment for `spec:matrix` (still true: started cards must have tests)

## Done when

- `node --test test/unit/matrix-scope.test.mjs`
- `node --test test/unit/checks.test.mjs` — passes by design: the old selection without "here" must stay unchanged (rule 10)
- `node -e "const s=require('fs').readFileSync('docs/card-lifecycle.md','utf8');if(!s.includes('another folder'))process.exit(1)"`
- `npm run saf:refresh -- --check`
- `npm run spec:matrix -- --check`
