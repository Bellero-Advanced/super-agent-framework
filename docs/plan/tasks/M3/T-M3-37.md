# T-M3-37 — L cards in steps

## Why

D-021: an L card is divided into steps inside the card — one commit per step, a stopped card resumes at the unfinished
step, and the reviewer reads step by step. The spec-reviewer is read-only and cannot run git, so the diff file itself
must be split by step. The engine part stays small: the plan check and the `task:diff` sections; the commit subject and
resuming are conventions the agents carry. [Spec rules 19–22](../../../specs/card-sizes.md#l-cards-in-steps-t-m3-37).

## What to do

- `plan.mjs`: `STEPS_HEADINGS` (`Steps`, `ขั้นตอน`) and `L_MIN_STEPS`; `parseCard` returns `card.steps` (numbered items
  of that section, outside code fences, in order) for every card; an L card with fewer than `L_MIN_STEPS` steps is the
  rule-19 issue
- `reviewdiff.mjs`: for a card with steps, find step commits on the first-parent history from the files base to `HEAD`
  (subject contains `<id> step <k>/`, `1 ≤ k ≤` steps), build the per-step sections and the `# steps` header line of
  rule 21 with the same file list and git options as today (argument arrays, `--literal-pathspecs`); the two fallback
  cases write today's whole diff with their header line; a card without steps keeps today's bytes. Lane cards are read
  in the worktree as today
- templates (rule 22): card template en/th — a `## Steps` / `## ขั้นตอน` section ("required for L: numbered steps,
  each finished by one commit `<id> step <k>/<n> <text>`"); plan README en/th — what an L card's steps are, how they are
  committed, resumed and reviewed; agents — designer (an L card lists its steps; each step is one commit's work),
  implementer (one commit per step with the rule-20 subject; resume at the first step without a commit:
  `git log --oneline <start>..HEAD`), spec-reviewer (on an L card read the diff file section by section in step order
  and name the step of each finding)
- re-render this repository's `docs/plan/README.md`, `docs/plan/tasks/_template.md`, `.claude/agents/*` (AGENT-AC-03
  needs them equal to the rendering) and bring the example's plan README and card template along
- `docs/card-lifecycle.md`: an "L cards in steps" part under Card format with rules 19–21 in plain words
- `test/unit/card-steps.test.mjs`: SIZE-AC-12, SIZE-AC-13 (temp git repo, real commits; a lane card once),
  SIZE-AC-14
