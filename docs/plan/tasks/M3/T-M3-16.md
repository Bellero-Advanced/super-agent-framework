# T-M3-16 — Setup keeps what it should, and says why

## Why

Proposed card A of [M3 "Carried to M3"](../../milestones/M3.md#carried-to-m3), part 1 (setup and upgrade data
safety). Review notes 02/F3 · 02/F4 · 27/Why · 20/N4 + 02/N5 · 20/N5 + 18/2 · 20/N1:

- a `same` file is rewritten, so a CRLF checkout becomes LF while the dry run says "same" (02/F4)
- a `keep-unplanned` file loses its manifest entry in setup (`next.files` is built fresh) while `refreshKitFiles` keeps
  it — the next run forgets SAF once wrote it (02/F3)
- `.saf/manifest.json` is read with a silent `{ files: {} }` default: a broken manifest makes every differing file
  "not written by SAF" and setup archives and replaces them (27/Why, listed in T-M2-27)
- `report.kept` mixes plain paths and decorated strings (20/N4, 02/N5)
- a `scripts` value that is not an object is replaced with `{}` (20/N5); a non-object root is reported as "not valid
  JSON" (18/2)
- the `OWNED_DIRS` doc comment is detached from it (20/N1)

[setup-rerun rules 28–31](../../../specs/setup-rerun.md#setup-keeps-what-it-should-plansetup--applysetup--refreshkitfiles-in-generatemjs) ·
[upgrade-scripts rules 12–13](../../../specs/upgrade-scripts.md#2-rules).

## What to do

- `applySetup`: skip writing actions whose `action === "same"` (the manifest entry is still recorded by `planSetup`)
- `planSetup`: copy the old manifest entry of every `keep-unplanned` path into `next.files` (as for `keep-edited`)
- one `readManifest(root)` helper: missing → `{ files: {} }`; present but not valid JSON, root not an object or `files`
  not an object → `planSetup` throws an error without a stack trace in the CLI (a `ConfigError`, or the error class the
  `saf.mjs` handler already prints without stack lines) — message `.saf/manifest.json is not readable — nothing was
  changed; restore it from git (git checkout -- .saf/manifest.json)`; `refreshKitFiles` pushes a warning naming the file
  and returns before writing
- `report.kept` = plain paths in setup and `refreshKitFiles`; one warning per kept path carries the reason
  (`keepLine` goes; `keep-unplanned` warning uses `REASONS["keep-unplanned"]`; refresh's edited file: `… edited in this
  project — kept`)
- `mergeScriptsText`: `scripts` present and not a plain object → `invalid: true, reason: "scripts"`; root not an object
  → `reason: "root"`; parse failure → `reason: "json"`. `planPackageJson` and `src/install.mjs`
  `mergeUpgradeScripts` print the rule 13 words from one small table in `generate.mjs` (export it; install imports it
  through `engineModule`)
- move the `OWNED_DIRS` doc comment onto `OWNED_DIRS`
- `test/unit/setup-dry-run.test.mjs`: the assertion "the real report keeps its decorated text" becomes the plain-path
  one (rule 31) — change nothing else there
- `test/unit/setup-keeps.test.mjs`: RERUN-AC-14, -15, -16 and UPG-AC-07 (ids in the names). AC-14 and AC-15 must fail on
  the code before this card
- `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then restore
  `examples/todo-api/.claude` and `examples/todo-api/package.json`
