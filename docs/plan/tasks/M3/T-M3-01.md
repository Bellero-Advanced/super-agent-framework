# T-M3-01 — Friction log: task:friction add|close, plan check, session count

## Why

When SAF itself gets in the way of a card the fact is lost unless someone writes a review note by hand (the notes of
T-M2-04 … T-M2-08 were never recorded). One append-only file with evidence lets the milestone end turn friction into
cards and lets small proven bugs be fixed at once. [Spec rules 1–14](../../../specs/friction-log.md#2-rules).

## What to do

- new `kit/tools-saf/lib/friction.mjs` (no dependency): `FRICTION_FILE`, `FRICTION_KINDS`, the marker, entry and
  closing patterns; `parseFriction(text)` → `{ entries: [{ id, date, kind, card, area, summary, evidence, status,
  line }], issues }`; `appendEntry(root, fields, { today })` and `appendClose(root, id, status, ref, { today })`
  (create the file with header and marker on first use; validate per rules 5, 7, 8; return the id)
- `plan.mjs`: `FRICTION_FILE` in `alwaysAllowed`; `loadPlan` reads the log into `plan.friction` and adds its issues
  with line numbers; `sessionContext` adds the friction line of rule 14 (laneSessionContext unchanged)
- `text.mjs`: the session line, en + th
- `bin/saf.mjs`: `task friction [add|close]` with the flags of rules 7–9; refused in a lane (rule 10, use the lane
  check the other main-folder commands use); usage line and header comment
- `config.mjs` `ENGINE_SCRIPTS` + `generate.mjs` `cmd.taskFriction`; `package.json` script `task:friction`;
  `examples/todo-api/package.json` gets it from `node bin/cli.mjs upgrade --dir examples/todo-api` (D-010)
- CLAUDE templates (en, th) and this repo's `CLAUDE.md`: one command line for `task:friction`; plan README templates
  (en, th) and `docs/plan/README.md`: a short section "Friction log" (what belongs there, the commands, commit it
  alone, lanes report it to the main session); `docs/card-lifecycle.md`: the same in user words; `docs/INDEX.md`:
  one row "Workflow friction (append-only)" → `docs/plan/friction.md`
- seed `docs/plan/friction.md` **with the new command** (not by hand), area and evidence as given; the header
  paragraph links `docs/plan/notes/M2-review-notes.md` as the earlier record:
  1. `workaround` · `examples/todo-api` · every kit card restores `examples/todo-api/.claude` and `package.json` by hand
     after the example upgrade · evidence: M2 cards "What to do"; M2-review-notes T-M2-10 C and T-M2-12 8
  2. `workaround` · `task:verify` · after a spec review fails, verifying again needs `task:start --restart`, which
     resets the attempt history · evidence: `kit/tools-saf/lib/task.mjs` verifyCard refusal "already passed";
     reviews of T-M2-10, T-M2-12 … T-M2-15 failed
  3. `workaround` · `docs/plan/notes` · non-blocking review notes of T-M2-04 and T-M2-06 … T-M2-08 were never written
     down · evidence: M2-review-notes section T-M2-04
  4. `doc-drift` · `docs/plan/README.md` · §1 says the evidence says "full suite deferred to gate"; the evidence JSON
     carries `deferred`/`targeted` · evidence: M2-review-notes T-M2-10 D
- `test/unit/friction.test.mjs`: temp projects; one test per scenario id in its name
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then
  `git checkout -- examples/todo-api/.claude`
