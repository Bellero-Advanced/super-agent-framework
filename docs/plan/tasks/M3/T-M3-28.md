# T-M3-28 — Role lanes are a project setting

## Why

The lane of a built-in role is fixed in `ROLE_LIBRARY`: `art-producer` cards (image generation, often long) work in the
main folder one at a time and block every other main-folder card although their files are separate. Owner order
2026-11-24. A worktree separates the files, so moving such a role to the code lane is safe; the main-folder lane stays
one card (D-018). Text for users in en and th — **role effort: high** (M2: text cards at `medium` bounced 3 of 4 times
at round 1). [Spec rules 1–7](../../../specs/role-lanes.md#2-rules) ·
[setup-choices rules 4–8, 10–11](../../../specs/setup-choices.md#2-rules).

## What to do

- `config.mjs`: `laneLocked: true` on `designer`, `spec-reviewer`, `release-operator` in `ROLE_LIBRARY`; `roleTable`
  reads `roles.lanes[name]` first (rule 3); `validateConfig` adds one error per bad key (locked · custom · unknown) —
  confirm `loadConfig` reaches it (RLANE-AC-04); `DEFAULTS.roles.lanes = {}`
- schema: `roles.lanes` — object, `additionalProperties: { "enum": ["code", "main"] }`
- confirm `laneOf`, `pickParallel` and `startCard` need no change (they read `roleTable`) — the tests prove it; a needed
  change there means stop and tell the designer
- `choices.mjs`: question `role-lanes` (group 6, `value`, key `roles.lanes`) with one explanation en + th; the
  `extra-roles` / `art-producer` explanation says "by default … unless roles.lanes moves it" (en + th); check every
  other explanation that names a lane
- `questions.md`: the row (asked only with worktree lanes on; recommended: leave empty); `docs/setup-questions.md`:
  the row; `docs/roles.md`: "Lane" = default lane + section "Moving a role to the other lane" (why safe, cost, locked
  roles and why — spec §1, rule 2); `docs/config-reference.md` `roles`: the key; `docs/card-lifecycle.md` lines ~69 and
  ~83: "by default" + link to `roles.md`
- in the verify notes: every sentence you add or change → the code that makes it true (agent rule)
- `test/unit/role-lanes.test.mjs`: RLANE-AC-01 … -07 (ids in the names), temp repos for AC-02/03
- refresh the copies: `npm run saf:refresh` once T-M3-27 has landed; beside it (parallel) the old way —
  `npm run saf:refresh`, `node bin/cli.mjs upgrade --dir examples/todo-api`, restore `examples/todo-api/.claude` and
