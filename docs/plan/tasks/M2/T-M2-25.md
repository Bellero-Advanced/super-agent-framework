# T-M2-25 — Lane caps go up to a high ceiling and each machine can set its own

## Why

Owner order (2026-11-24, D-018 proposed): cards already cannot overlap, so how many run at once depends on the
machine — the code-lane and side-lane caps stop at a low schema maximum and can only be changed for the whole team in
the tracked `saf.config.json`. [Spec rules 1–9](../../../specs/lane-caps.md#2-rules).

Ceiling `LANE_CEILING = 32`: a typo guard, not advice. Each lane is a full worktree plus the lane install step, so a
machine runs out of disk, memory or CPU long before 32 for most projects; with the default ports (`lanePorts` in
`DEFAULTS`) lane 32 is still far below the TCP limit, and a custom high `base` is caught by the port check (rule 3)
instead of a lower ceiling. No ceiling at all was rejected: a typo (`300` for `3`) would then make `task:next
--parallel` offer every non-overlapping card at once.

## What to do

- `config.mjs`: export `LANE_CEILING = 32` and `MAX_PORT = 65535` (with one-line comments); `LOCAL_KEYS` =
  `["workflow.testMode", "workflow.lanes.code", "workflow.sideLanes.max"]`
- schema: `workflow.lanes.code.maximum` and `workflow.sideLanes.max.maximum` = 32; `lanes.main` unchanged (1–1)
- `loadConfig`: apply every `LOCAL_KEYS` key from the local file with one loop (set the dotted path on the resolved
  config); keep the test-mode source and `SAF_TEST_MODE` exactly as today; set `config.workflow.localKeys` (array of
  the keys the local file set, `[]` without a file). No env variable for lane caps (rule 5)
- `loadConfig`, after the local file: port check of rule 3 — error names the three keys and the file the code cap came
  from; skipped when worktrees are off, `lanes.code` is 0 or `lanePorts.env` is empty
- `parallel.mjs` `pickParallel`: the "code lane is full" and "side lanes are full" reasons end with
  ` (this machine: saf.config.local.json)` when the cap's key is in `config.workflow.localKeys` (use
  `LOCAL_CONFIG_FILE`, not the literal); `task.mjs` the `side lanes are full` error of `task:start` likewise
- `choices.mjs` `MACHINE_SWITCHES`: one en + th line for each new local key ("cap … for this machine only"); the
  setup-choices tests require a line per `LOCAL_KEYS` key
- `test-mode-config.test.mjs`: the tables test expects the new `LOCAL_KEYS`; the TMODE-AC-03 fixture uses
  `workflow.lanes.main` instead of `workflow.lanes.code` (spec row already changed)
- `test/unit/lane-caps.test.mjs`: one test per LCAP-AC-01 … 05 (ids in the test names); AC-05 renders a project with
  and without a local file that sets both caps and compares every generated file byte for byte
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then restore
  `examples/todo-api/.claude` and `examples/todo-api/package.json`
