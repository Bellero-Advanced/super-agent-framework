# T-M2-26 — Explanations and docs tell the truth about lane caps

## Why

After T-M2-25 the lane caps go much higher and can be set per machine, but every text a person reads still says the
local file holds "only `workflow.testMode`", and no text says why the main-folder lane is fixed at one or what each extra
lane really costs. [Spec rules 10–12](../../../specs/lane-caps.md#explanations-and-docs).

## What to do

- `choices.mjs` `CHOICES`, en and th, every sentence true of the code, within `FIELD_MAX`, no digits:
  - `lanes` `on`: cost = a worktree (full checkout) plus the lane install step, and CPU, memory and disk while it builds
    and tests
  - `lanes` `on-custom`: you set the code-lane cap for the project, and each person can set it for their own machine in
    `saf.config.local.json`; the main-folder lane stays one card because cards there share one folder and verify tells
    cards apart by their start commit
  - `side-lanes` `on` / `on-more`: side cards still only take free lane slots; the side cap can also be set per machine
- plan README templates (en, th): line 34 (test mode per machine) names all local keys or points to config-reference;
  the side-lane and caps lines (77, 97 en · 77, 95 th) add "project caps — a machine may set its own in
  `saf.config.local.json`"; keep the `{{workflow.…}}` values (they show the project's caps, rule 8)
- `SKILL.md` (Step 1 test-mode paragraph and Step 2 per-machine sentence) and `questions.md` (group 6 rows for lanes and
  side lanes, and the test-mode per-machine paragraph): the local file may hold `workflow.testMode`,
  `workflow.lanes.code`, `workflow.sideLanes.max`; when the person says the machine is strong or weak, offer to write
  the caps there; no env variable for caps
- `docs/config-reference.md`: `lanes` row (code up to `LANE_CEILING` in `config.mjs`; main fixed at one and why),
  `sideLanes` row (never adds slots), `saf.config.local.json` section (three keys, example with a cap, source order per
  key, port check)
- `docs/card-lifecycle.md`: Parallel lanes (why the main lane is one; caps per machine), Side lanes (cap per machine),
  Test mode "Per machine" (no longer "holding only `workflow.testMode`")
- `test/unit/lane-caps-docs.test.mjs`: LCAP-AC-06 (id in the test name)
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then restore
  `examples/todo-api/.claude` and `examples/todo-api/package.json`
