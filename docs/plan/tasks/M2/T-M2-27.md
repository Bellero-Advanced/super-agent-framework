# T-M2-27 — An unreadable settings.local.json is archived, never overwritten

## Why

Real data loss (review note F1 of T-M2-02): when `.claude/settings.json` has an `env` block that moves,
`planSettings` reads `.claude/settings.local.json` with `readJson(…, {})` — an invalid file becomes `{}` and is
overwritten with just the moved `env`, losing the person's local permissions and possibly secret values, with no
archive and no warning. A valid-JSON root that is not an object loses data too: `[]` gets `env` as an array property
that `JSON.stringify` drops (the moved `env` values vanish from both files), and `null` crashes setup.
[Spec rules 19–22](../../../specs/setup-rerun.md#settings-files-are-never-lost-plansettings-in-generatemjs).

The archive goes to `ARCHIVE` like an unreadable `settings.json`, but because the local file may hold secrets the
archive path must be git-ignored (setup's own commit step and a later `git add -A` would otherwise track it).

Same class, checked and **not** in this card (no data destroyed; listed in the M2 review-notes triage):
- `planSetup` and `refreshKitFiles` read `.saf/manifest.json` with a `{ files: {} }` default — on a re-run with a
  broken manifest every differing rendered file counts as "not written by SAF" and is archived and replaced (moved, not
  lost); `refreshKitFiles` keeps every differing command/skill (safe direction)
- `refreshKitFiles` reads `saf.config.json` with a `{}` default, and `validateConfig({})` passes — an invalid JSON
  config refreshes `/saf` commands and skills with default settings and no warning; `upgrade()` then crashes on the
  same file (`src/install.mjs`, T-M2-18 note 5)
- `src/install.mjs` `mergeUpgradeScripts` and `readVersion`, `choices.mjs` `languageFor`: defaults that skip work with
  a warning or fall back to English — no loss

## What to do

- `generate.mjs`: an `unreadable(json)` helper (parse failure or non-object root); `planSettings` uses it for both
  files; an unreadable `settings.json` with an object-less root is archived like invalid JSON
- when `env` moves and the local file exists and is unreadable: `localArchivedTo = archiveDest(root, SETTINGS_LOCAL,
  taken)`, start the new local object from `{}`; return it in the settings merge
- `generate()`: `moveAside` the local file before `writeAt`; push `archiveLine(SETTINGS_LOCAL, dest)` to
  `report.archived` and a warning naming both paths (no values)
- dry-run settings line (`~generate.mjs:681`): add `— <SETTINGS_LOCAL> not valid JSON, archived to <dest>`
- `GITIGNORE_LINES`: add `` `${ARCHIVE}/${SETTINGS_LOCAL}*` `` (define the constants above the table if needed); add the
  same line to this repo's `.gitignore` and `examples/todo-api/.gitignore`
- `test/unit/settings-archive.test.mjs`: RERUN-AC-08 and RERUN-AC-09 (ids in the names); AC-08 must fail on the code
  before this card (the old local file is gone and nothing is archived); use a real git repo for `git check-ignore`
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then restore
  `examples/todo-api/.claude` and `examples/todo-api/package.json`

## Out of scope

- The manifest and `saf.config.json` defaults listed above (M3 / cheap-fix list in the triage)
- Archiving an unreadable local file when no `env` block moves (it is not touched then — rule 22)
