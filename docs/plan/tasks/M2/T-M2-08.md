# T-M2-08 — task:merge skips the deferred full suite and the milestone gate always runs it

## Why

A lane card today runs the full suite twice: at verify and again at merge. In `milestone` mode it runs once per
milestone, and the exit gate is where it must not be skipped —
[spec rules 18–20](../../../specs/test-mode.md#merge-and-the-exit-gate).

## What to do

- `testmode.mjs`: `mergeChecksFor(config)` — `mergeChecks` without full-suite commands in `milestone` mode, unchanged
  otherwise
- `mergeCard` in `task.mjs`: use `mergeChecksFor` when `opts.checks` is not given; print
  `skipped (full suite deferred to gate): <commands>`; return the skipped list with the result
- `verifyMilestone` in `task.mjs`, `milestone` mode only: if no gate's `run:` holds a full-suite command, add a gate
  `{ id: "full-suite", text: "the full test suite (deferred from the cards)" }` that runs every full-suite command;
  milestone evidence gets `testMode` and `deferredCards` (cards of the milestone whose evidence has `deferred`)
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api` after changing `kit/`
- tests in `test/unit/test-mode-gate.test.mjs`, named with the scenario ids

## Out of scope

- the culprit search and its hint on a failed gate (T-M2-09)
