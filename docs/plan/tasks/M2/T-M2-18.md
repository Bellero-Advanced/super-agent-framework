# T-M2-18 — saf upgrade adds the engine's new package.json scripts (task:culprit) without touching existing ones

## Why

T-M2-09 added `task:culprit` to `ENGINE_SCRIPTS`, and the exit-gate hint (and, after T-M2-10, the generated
CLAUDE.md) prints `npm run task:culprit -- <M>`. But `upgrade` never merges scripts, so every existing project —
`examples/todo-api` included — has no such script after `saf upgrade`. (T-M2-09's card said "`saf:refresh` merges
it"; it only worked here because T-M2-09 edited this repo's `package.json` by hand.)
[Spec rules 1–11](../../../specs/upgrade-scripts.md#2-rules).

## What to do

- `kit/tools-saf/lib/generate.mjs`: move the wanted-script list out of `mergePackageJson` into an exported
  `engineScripts(config)` (`saf` + `ENGINE_SCRIPTS`, `measure` only when `workflow.measure.enabled`);
  `mergePackageJson` calls it — setup behaviour unchanged (rule 1)
- `src/install.mjs` `upgrade()`: after `copyKit`, before `refreshKitFiles` (rule 10), a small `mergeUpgradeScripts`:
  - read and validate `saf.config.json` with the copied engine's `config.mjs`; missing/invalid → warning, no change
  - `packageManager: "none"` → skip without reading `package.json` (rule 7); no `package.json` → one line, never
    create it (rule 8); invalid JSON → warning, no change (rule 9)
  - add only missing keys from `engineScripts(resolveConfig(raw))`; a different existing value → kept + listed (rule 3)
  - write only when a key was added, keeping the detected indentation and trailing newline (rules 5–6)
  - log `  added script: <name>` / `  kept script: <name> (SAF expects "<value>")`; return `scripts: { added, kept }`
- update the file comment of `src/install.mjs` ("never touches project content" → except adding missing scripts) and
  `docs/upgrade.md` (one bullet: adds missing engine scripts to `package.json`, never changes existing ones)
- run `npm run saf:refresh` (this repo's `package.json` already has every script → must stay byte-identical; it is
  in `dont_touch`) and `node bin/cli.mjs upgrade --dir examples/todo-api` (adds `task:culprit` to
  `examples/todo-api/package.json`)
- `test/unit/upgrade-scripts.test.mjs`: temp projects via `init(root, { answers })`, then edit `package.json` and call
  `upgrade(root)`; one test per scenario id in its name; UPG-AC-06 reads `examples/todo-api/package.json` and
  `examples/todo-api/saf.config.json` and compares with `engineScripts`

## Out of scope

- the exit-gate hint and the templates — they stay on the project's script runner (`cmd()` / `{{cmd.taskCulprit}}`);
  no raw-form fallback
- docs that mention `task:culprit` (T-M2-10)
