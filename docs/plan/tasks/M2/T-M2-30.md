# T-M2-30 — An env block setup cannot merge is archived; a colliding key keeps the local value

## Why

Same data-loss class as T-M2-27 (review note 27/N2, owner order 2026-11-24). In `planSettings`
(`kit/tools-saf/lib/generate.mjs`, the `if (s.env)` branch) the moved block is spread over the local one:
`local.env = { ...(local.env ?? {}), ...s.env }`, then `delete s.env`.

1. A key both files hold takes the `settings.json` value; the person's local value (often a machine-specific secret) is
   overwritten with no archive and no warning. The project value is not kept anywhere on disk either once
   `settings.json` loses its `env` block (git history only).
2. A string or array `env` spreads into index keys (`"abc"` → `{ "0": "a", "1": "b", "2": "c" }`) in either file; a
   number or `true` spreads to nothing and the value vanishes from both files.

[Spec rules 24–27](../../../specs/setup-rerun.md#env-blocks-that-cannot-be-merged-plansettings-in-generatemjs):
an `env` that is not a plain object is unreadable for merging → the file that holds it is archived and nothing moves
silently; a collision keeps the **local** value and archives `settings.json` (git-ignored by
`${ARCHIVE}/${SETTINGS}*` in `GITIGNORE_LINES`, so a copied secret stays untracked).

Which file is archived, per case:

| case | archived | new `settings.json` | new `settings.local.json` |
|---|---|---|---|
| `settings.json` `env` not an object | `settings.json` | without `env`, with hooks | untouched (not read) |
| local `env` not an object, project `env` object | `settings.local.json` | without `env` | old other keys + `env` = moved block |
| both objects, a key with different values | `settings.json` | without `env` | combined, local value wins |
| both objects, no differing key | nothing | without `env` | combined (as today) |

## What to do

- `generate.mjs`: a `mergeable(v)` helper (plain object: not `null`, not an array). In `planSettings`, test
  `Object.hasOwn(s, "env")` instead of `s.env` truthiness, so `null`, `0`, `false` and `""` count too
- not mergeable in `settings.json` → `archivedTo = archiveDest(root, SETTINGS, taken)` (only if not already set by the
  unreadable-file branch), `delete s.env`, do not read the local file, `envMoved: false`; warning:
  `` `${SETTINGS} env is not a JSON object — archived to ${dest}; nothing was moved to ${SETTINGS_LOCAL}` ``
- local file readable but its `env` not mergeable → `localArchivedTo` as in T-M2-27's branch; keep the other keys,
  set `env` to a copy of the moved block; warning naming both paths
- both mergeable → `{ ...s.env, ...local.env }` (local wins); count keys present in both with different values
  (compare `JSON.stringify` of each value); count > 0 → archive `settings.json` (same `archivedTo`), warning:
  `` `${n} env key(s) set in both files with different values — kept the values of ${SETTINGS_LOCAL}; the values of ${SETTINGS} are in ${dest}` ``
  (a number only, never a key value)
- return `archivedWhy` / `localArchivedWhy` (`"not valid JSON"` · `"env is not a JSON object"` · `"env values differ
  from .claude/settings.local.json"`) with the targets; `planLines` uses them instead of the fixed "not valid JSON" text
  for both settings parts of the line; `planSetup` already pushes both targets to `report.archived`
- keep the "moved the env block … values were not printed" warning only when a block really moved
- `test/unit/settings-env-merge.test.mjs`: RERUN-AC-12 and RERUN-AC-13 (ids in the test names), through `planSetup`,
  `setup --dry-run` (CLI) and `generate`; assert the archives byte for byte, the exact new `env` objects, no `"0"` key,
  no fixture value (use distinctive values such as `local-secret-1`) in stdout, stderr, warnings or `report`, and
  `git check-ignore` on every archive path in a real git repo. Both must fail on the code before this card (AC-12:
  `A` becomes the project value and nothing is archived; AC-13: index keys)
- spec: only if the build shows a rule cannot be met as written — say why in the card's verify notes
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then restore
  `examples/todo-api/.claude` and `examples/todo-api/package.json`
