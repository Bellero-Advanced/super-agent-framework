# T-M2-16 — The milestone gate runs every full-suite command no declared gate runs, and the gate id full-suite is reserved

## Why

In `milestone` mode card verify defers the full suite and `task:merge` skips it, so the exit gate is the only place it
runs. Today the extra gate is added only when no declared gate runs *any* full-suite command: with `test` and `e2e`
set and a gate that runs only `npm test`, the e2e command never runs at all —
[spec rule 19](../../../specs/test-mode.md#merge-and-the-exit-gate). A declared gate named `full-suite` would also
collide with the extra gate in the evidence and the plan views —
[spec rule 28](../../../specs/test-mode.md#the-full-suite-gate-in-the-plan-files).

## What to do

- `testmode.mjs` `gatesWithFullSuite(config, gates)`: in a mode where `GATE_ADDS_FULL_SUITE` is true, `run` = the
  commands of `fullSuiteCommands(config)` that no declared gate's `run:` contains (match with `isFullSuite` on each
  gate command, so trimming works as in rule 9); add `{ ...FULL_SUITE_GATE, run }` only when that list is not empty.
  Other modes unchanged
- `plan.mjs` milestone parsing: a gate whose id equals `FULL_SUITE_GATE.id` (import it from `testmode.mjs` — no import
  cycle) is a plan issue `<file>: gate id "full-suite" is reserved for the extra exit gate (test mode) — rename it`.
  In every mode (the plan check must not depend on per-machine settings, rule 6). `task:verify <M>` already refuses
  on plan issues through `requireValid` — no change in `task.mjs`
- `test/unit/test-mode-gate.test.mjs`: the T-M2-08 test "no extra gate when a gate already runs a full-suite command"
  encodes the gap (its config sets `test` and `e2e`, its gate runs only `npm test`). Change only that case so the
  declared gate runs both commands; leave the other T-M2-08 tests as they are
- new `test/unit/test-mode-gate-coverage.test.mjs`, named with the scenario ids:
  - TMODE-AC-14: gate `npm test` only → gates `[G1, full-suite]`, `full-suite.run` equals `["npm run test:e2e"]`,
    commands ran `npm test` once and the e2e command once; gates running both → no extra gate; a gate command with
    extra spaces around `npm test` still counts as covering it
  - TMODE-AC-15: a milestone file with gate id `full-suite` → `loadPlan` reports an issue naming `full-suite` and
    the file; `verifyMilestone` throws before any command runs (fake runner records nothing)
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api` after changing `kit/` (the copies
  are in `workflow.alwaysAllowed`)
