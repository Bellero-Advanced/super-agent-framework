# T-M2-11 — The lane guard recognises a lane worktree on Windows too (CI matrix green again)

## Why

CI is red on `windows-latest` (node 20 and 22) since commit `72ad81c`; macOS and Linux are green. The unit test
"lane guard: a SAF project in a subfolder … a lane root that lost its label is still refused"
(`test/unit/task.test.mjs`) fails with `Missing expected exception`: `laneFolder()` returns `null` for a lane worktree
root that lost its label instead of refusing it. On Windows a person whose lane label got lost would silently be
treated as "not a lane". The M2 gate `project-checks` needs the CI matrix green. This is non-blocking notes 1 and 2
of the T-M2-04 spec review.

Likely cause (from the CI log and the code, not yet run on Windows):

- `laneFolder()` in `kit/tools-saf/lib/task.mjs` computes
  `linked = !isMainFolder(root) && topLevel(root) === realpathSync(root)`. `topLevel()` in `kit/tools-saf/lib/git.mjs`
  returns `realpathSync(git rev-parse --show-toplevel)`. The test folder is under the Windows temp dir
  (`C:\Users\RUNNER~1\…`); git prints the long name and JS `realpathSync` does not expand 8.3 short names, so the two
  strings differ → `linked` is false.
- `atPath` uses `dirname(root).endsWith(wtDir)`; `wtDir` is written with `/` (`.claude/worktrees`) while `dirname` on
  Windows returns `\` — so `atPath` is probably never set on Windows either. Confirm and fix it in the same card.
- With the open evidence naming the branch (`owner` set), `owner && !linked && !atPath` then returns `null`.

## What to do

- **Reproduce without a Windows machine:** add a small exported helper, e.g. `samePath(a, b)` in
  `kit/tools-saf/lib/git.mjs`, that resolves both sides with `realpathSync.native` (falls back to the plain string
  when the path does not exist) and compares them. Unit test first: two different spellings of the same folder
  (a symlink or a `..` segment on macOS/Linux; on win32 an 8.3 short name, test skipped elsewhere) are the same path;
  two different folders are not. The test must fail against a comparison that normalises the two sides differently
  (the current `topLevel(root) === realpathSync(root)`)
- **Fix both places:** `topLevel()` uses `realpathSync.native`; `laneFolder()` decides `linked` with
  `samePath(topLevel(root), root)` (no extra case folding on win32 — `.native` already returns the on-disk spelling).
  Make the `atPath` check separator-safe (compare normalised paths, e.g. with `path.join`/`sep`, not a raw `/` string)
- **Prove the top-level check for real (review note 2):** today the refused-root assertion would also pass if `linked`
  were always false, because the open evidence and the worktree path already reveal the lane. Add a case where only
  the branch name reveals the lane — a linked worktree on a `card/*` branch with no lane label, no open evidence for
  it, and not under `worktreeDir` — and assert it is refused with `no lane label`; keep the subfolder case returning
  `null`
- **Engine copies:** after changing `kit/`, run `npm run saf:refresh` and
  `node bin/cli.mjs upgrade --dir examples/todo-api` (`test/unit/dogfood.test.mjs` fails while they differ). The
  copies are in `workflow.alwaysAllowed` (D-007), so they are not in `touch` and not counted in the size check
- **Final proof is CI:** the card is right only when the GitHub Actions matrix (Linux, macOS, Windows × node 20 and
  22) is green on the pushed commit. Pushing needs the owner's order; the main session attaches the CI run link and
  result to the evidence / review. Local `task:verify` passing on macOS is necessary, not sufficient
