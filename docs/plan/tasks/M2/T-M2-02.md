# T-M2-02 — saf setup --dry-run lists what a setup run would do

## Why

Before re-generating, people want to see which files setup would create, update, archive or keep — today the only
way to find out is to run it. The list must be what really happens, so the real run and the dry run share one code
path. [Spec rules 4, 8, 11–13](../../../specs/setup-rerun.md#seeing-it-first).

## What to do

- `kit/tools-saf/lib/generate.mjs`: split `generate()` into `planSetup(root, answers, opts)` (computes everything,
  writes nothing) and an apply step; `generate()` = apply(planSetup(...)), returning the same `{ config, report,
  detected }` as today
  - per rendered file one action: `create` · `same` · `update` · `replace-edited` · `keep-edited` (the living-file
    rule of T-M2-20 moves here) · plus `remove` / `keep-unplanned` from `retireUnplanned` (make it compute, then apply)
  - merges as data: `.gitignore` lines to add, `package.json` result of the shared script merge (create · added ·
    kept · invalid), `.claude/settings.json` hooks to add and env move, `saf.config.json` same/update, the adopt
    archive list (first run), the regenerated `docs/plan/STATE.md` / `.saf/plan.md` / manifest
  - the `mergeChecks` filter needs the would-be scripts: take them from the planned `package.json` merge in memory
- `kit/tools-saf/bin/saf.mjs` `setup`: `--dry-run` prints `setup --dry-run: nothing was written`, then one line per
  path (action · path · reason) and the merges; exit 0; honours `--adopt` / `--no-adopt`; update the usage line and
  the file-header command list
- `test/unit/setup-dry-run.test.mjs`, names with the scenario ids: AC-03 hashes every file of the tree before and
  after (set-up project with edits, and an empty folder — no `.saf/` appears), calling both `planSetup` and the CLI
  (spawn `kit/tools-saf/bin/saf.mjs setup --answers … --dry-run` in the temp folder); AC-04 builds one fixture with every action and
  compares `planSetup` actions with the real `generate` report lists
- existing `test/unit/generate.test.mjs` and e2e tests must pass unchanged (behaviour-preserving refactor)
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then
  `git checkout -- examples/todo-api/.claude examples/todo-api/package.json`
