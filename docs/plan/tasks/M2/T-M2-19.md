# T-M2-19 — The release-operator agent follows policies.push

## Why

With `policies.push: allowed`, `CLAUDE.md` and the decision log say pushing is allowed, but the generated
release-operator agent still says "Never push" — two generated files contradict each other, and the `push: allowed`
explanation that `/saf-setup` now shows has to admit the bug
([spec rule 23](../../../specs/setup-choices.md#setup-flow-and-generated-files), review note N1 of T-M2-14).

## What to do

- `kit/tools-saf/templates/agents/release-operator.md` line 27: an `{{else}}` branch on `pushOwner` —
  owner-order keeps "Never push without the {{owner}}'s order"; allowed says pushing is allowed. "never force-push or
  rewrite history" stays in both branches. Agent templates exist once (English; agents report in English), so there
  is no th copy
- `kit/tools-saf/lib/choices.mjs`: the en and th `what` field of `E("push", "allowed", …)` drops "the release-operator
  file, if enabled, still says never push" and says the release-operator file (if enabled) says the same; keep every
  field within `FIELD_MAX` and free of digit runs (AC-05 still passes)
- a test in `test/unit/generate.test.mjs` named with `SETUP-AC-10`: generate with the release-operator role enabled
  and `policies.push` `owner-order`, then `allowed`; assert the agent file's push line for each, "force-push" in both,
  and that neither `push: allowed` explanation mentions "never push" / "ห้าม push"
- run `npm run saf:refresh` after changing `kit/`

## Out of scope

- `policies.noForcePush: false` still renders "never force-push" in this file (stricter than CLAUDE.md, safe) ·
  the deploy-allowed "order step" in the same file (note N6, batched) · a real push guard hook (note N4, batched)
