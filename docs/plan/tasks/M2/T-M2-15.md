# T-M2-15 — /saf-setup shows the four lines for every option and lists the settings it did not ask

## Why

The explanations and the not-asked list help only when the interview shows them —
[spec rules 16–20](../../../specs/setup-choices.md#the-interview-kitclaudeskillssaf-setup). And the `adopt: no`
explanation is only true when the skill passes `--no-adopt` — today it passes nothing for "no", `setup` falls back to
detection and archives anyway ([rules 21–22](../../../specs/setup-choices.md#setup-flow-and-generated-files), review
note N2 of T-M2-14).

## What to do

- `SKILL.md` Step 1: before each group run `node tools/saf/bin/saf.mjs choices --group <g> --lang <chat language>`,
  show each question's options as a compact table (option · what it is · good for · cost · pick it when) as printed,
  put the "pick it when" line in the AskUserQuestion option descriptions; skipped (detected) questions show the
  detected value and offer the explanation only on request. Groups, order and "(recommended)" stay as they are
- `SKILL.md` Step 2: after the summary table run `choices --not-asked --lang <chat language>` and ask once:
  Generate (recommended) · Change an answer · Adjust a setting that was not asked (keys and values in one plain
  message → added to `.saf/setup-answers.json`)
- `SKILL.md` Step 1: when `detect` reports `adopt: true` and this is not a re-run, ask the adopt question explicitly
  ("keep the old docs as history?") with the `choices --group flow` explanations; a new project skips it and says so
- `SKILL.md` Step 3: always pass exactly one flag — `--adopt` for "yes", `--no-adopt` for "no" or a skipped question;
  say why in one line (without a flag `setup` falls back to detection)
- `questions.md`: one line under the title — the option explanations come from `saf choices`; this file keeps the
  questions, keys and recommended defaults (no explanation text here). Add a short "Setup flow" list (not a table with
  a Key column, so the AC-02 key comparison is unchanged): adopt — recommended "yes" for an existing project; commit
  the setup locally — recommended "yes"
- `kit/tools-saf/lib/choices.mjs`: one change only — the `DOCS_URL` anchor printed by `--not-asked` is the key's
  top-level part in lowercase (spec rule 13; review note 3 of T-M2-12). No explanation text changes here
- `docs/config-reference.md`: every schema leaf key named in backticks in its top-level section (fill the gaps, e.g.
  `measure.waitMs` · `maxLoadPerCore` · `names`, `secrets.extraPatterns`, `models.overrides`); one heading per
  top-level key whose GitHub anchor equals the lowercase `DOCS_URL` anchor (split combined headings such as
  `models · roles` and `tokenSaving · firstMilestone`)
- `docs/setup-questions.md`: two sentences — the four lines per option and the not-asked list at the confirm step, with
  the two `saf choices` commands; do not copy explanations
- tests in `test/unit/setup-choices.test.mjs`, named with the scenario ids: AC-07 reads `docs/config-reference.md`
  against the schema leaves and checks every anchor printed by `choices --not-asked` is lowercase and matches a
  heading's GitHub anchor; AC-08 reads `SKILL.md`; AC-09 reads `SKILL.md` (adopt question in Step 1, `--adopt` and
  `--no-adopt` in Step 3) and `questions.md` (adopt recommendation)
- run `npm run saf:refresh` after changing `kit/claude/skills/saf-setup/`
