# T-M2-12 — saf choices --not-asked lists every setting the interview does not ask, and where to change it

## Why

About a fifth of the settings in `saf.config.json` are never asked in `/saf-setup` and stay invisible (command
timeout, measure lock wait, lane install, extra secret patterns …). A person on a slow machine or in a bigger team
cannot adapt what they do not know exists. This card makes the full list printable and keeps it complete with a test —
[spec rules 1–2, 9–11, 13–15](../../../specs/setup-choices.md#2-rules).

## What to do

- new `kit/tools-saf/lib/choices.mjs` (data first, small helpers after):
  - `QUESTIONS` — one row per interview question: `id` · `group` (1–8 or `flow`) · `keys` (full dotted paths) ·
    `kind` (`choice` · `value` · `identity`) · `options` for `choice` questions. Follow `questions.md` group by
    group, including the two test-mode rows T-M2-10 added (`workflow.testMode` · `stack.commands.testFiles`) and the
    `flow` questions adopt and commit (spec rule 3). A `questions.md` row that sets two independent booleans
    (monorepo · submodules) may be two questions
  - option values: from the source where one exists (schema enum · `yes`/`no` for booleans · optional roles of
    `ROLE_LIBRARY` · `SKILL_PACKS` — import them, do not retype them); listed values otherwise (lanes `on` ·
    `on-custom` · `off`, …)
  - `INTERNAL_KEYS` (`$schema` · `version`) · `NOT_ASKED` — `key → { en, th }` one-line summary for every schema leaf
    that no question sets · `MACHINE_SWITCHES` — one `{ en, th }` line for every `LOCAL_KEYS` key and for the env
    variables `TEST_MODE_ENV` and `STOP_HOOK_ENV` (import the names) · `LABELS` (en, th) · `DOCS_URL` (the GitHub URL of
    `docs/config-reference.md`; the key's top-level section is the anchor)
  - `schemaLeaves(schema)` — dotted leaf paths (rule 10) · `notAskedText(lang)` — the rule 13 output
- `bin/saf.mjs`: `choices --not-asked [--lang en|th]` (rules 13–15); the `--group` form comes in T-M2-13 — until then
  `--group` is a usage error. Add `choices` to the usage lines
- `questions.md`: the Key column holds full dotted keys only — write out `policies.deploy.target` /
  `.exceptions`, `stack.commands.typecheck` … `build`, `tokenSaving.enabled` … (no `.x` shorthand, no `*`); no other
  text changes
- tests in `test/unit/setup-choices.test.mjs`, named with the scenario ids:
  - AC-01 on the real schema, plus a fixture schema with one extra key that must fail naming the key
  - AC-02 parses the Key column of every table in `questions.md` that has one and compares sets both ways
  - AC-03 runs the CLI in a temporary folder: without `saf.config.json`, with `chatLanguage: "th"`, with `--lang en`;
    asserts exit 0 and that the folder is unchanged
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api` after changing `kit/`

## Out of scope

- option explanations (T-M2-13, T-M2-14) · skill wiring and docs (T-M2-15)
- new keys in `LOCAL_KEYS` — out of scope of the spec
