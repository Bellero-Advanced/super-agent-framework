# T-M2-04 — task:verify reports changed code and test lines against the card's size cap

## Why

Size caps (S ≤ 150 code lines, tests ≤ 250) are written on every card but nothing measures them.

## What to do

- Count added + removed lines from the start commit, split into code and test files (test globs from the config)
- Over the cap: a warning in the verify output and in the evidence (not a failure — the reviewer decides)
- Tests: a card under the cap, one over, test lines counted apart
- **Lane guard fix (needed so this card's own `npm test` can pass in its lane):** `laneFolder()` in
  `kit/tools-saf/lib/task.mjs` treats any folder without a `.git` directory as a linked worktree. A SAF project in a
  subfolder of a repo (here `examples/todo-api`, which `test/e2e/example.test.mjs` runs) on a `card/*` branch is then
  refused with "no lane label .saf-lane.json but this is the worktree of lane card …". Fix: the guess from the branch
  name applies only when the folder is the top level of a linked git worktree (`git rev-parse --show-toplevel` equals
  the folder); a SAF project in a subfolder gets `null` (not a lane) unless its own evidence names the branch.
  Unit test in `test/unit/task.test.mjs`: a SAF project in a subfolder of a lane worktree runs `task state --check`
  without the refusal; a lane worktree root that lost its label is still refused
- **Engine copies:** after changing `kit/`, run `npm run saf:refresh` and
  `node bin/cli.mjs upgrade --dir examples/todo-api` — `test/unit/dogfood.test.mjs` fails while the copies differ. The
  four copied files are in `touch` for that reason only; never edit them by hand

## Size

Count only hand-written lines: `kit/` + `docs/` (code) and `test/` (tests). The four engine copies repeat the `kit/`
change byte for byte, so the size warning in this card's evidence over-counts code lines up to three times. The
spec-reviewer judges the size from `kit/` and `test/` only. Decision D-007 (proposed) would add the copies to
`workflow.alwaysAllowed` in `saf.config.json` so they are not counted at all; no engine change is needed for that.

## Out of scope

- Anything not named above — its own card
- Excluding generated paths from the size count in engine code (D-007 handles it through config)
