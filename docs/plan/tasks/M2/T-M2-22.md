# T-M2-22 — /saf-setup re-run shows what would change and asks per edited file

## Why

The dry run and `--keep` help only when the interview uses them: a person re-running setup should see the list and
decide per edited file before anything is written. [Spec rules 16–18](../../../specs/setup-rerun.md#the-interview-kitclaudeskillssaf-setupskillmd).

## What to do

- `SKILL.md` Step 0: a re-run is detected by `.saf/manifest.json` (the engine's test), not by the shape of
  `saf.config.json` (closes the mismatch of review note N6 of T-M2-15 for this flow)
- `SKILL.md` Step 3, on a re-run, before `setup`: run `setup --answers .saf/setup-answers.json --dry-run` (with the
  adopt flag of Step 1), show the list; for each `replace-edited` file ask once (AskUserQuestion): Take the new
  version — yours is archived to `docs/archive/pre-saf/` (recommended) · Keep mine · Show the diff first (run
  `--dry-run --diff`, show that file's part, ask again); pass kept files with `--keep`; list living files that will be
  kept with the one-line note of spec rule 17
- `SKILL.md` "Re-running" and `docs/upgrade.md`: living files with edits are kept, other edited files are archived and
  replaced unless kept, `--dry-run` / `--diff` show it first (replace the T-M2-20 sentence)
- keep SETUP-AC-08 and SETUP-AC-09 green (the Step 1 / Step 2 / Step 3 texts they read stay)
- `test/unit/setup-rerun-docs.test.mjs`: one test named with `RERUN-AC-07`
- run `npm run saf:refresh`
