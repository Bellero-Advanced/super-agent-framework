# T-M2-14 — Option explanations for groups 5–8 and the setup-flow questions

## Why

The workflow and policy questions are where a person adapts SAF to their machine and team: parallel lanes, side
lanes, the measure lock, test mode, push and deploy rules, token saving. They need the same four lines as groups 1–4,
and a test must keep every future option explained —
[spec rules 3, 5–7](../../../specs/setup-choices.md#the-data-table).

## What to do

- `choices.mjs` — `CHOICES` entries for every `choice` and `value` question of groups 5–8 (roles and skills ·
  workflow · policies · token saving) and of `flow` (adopt · commit), same rules as T-M2-13. Machine and team
  questions say plainly what they cost on a slow machine or in a team (for example: more code lanes = more parallel
  work but more CPU and disk; test mode `milestone` = fastest, a break shows up only at the exit gate and
  `task:culprit` finds the card). The test-mode entries describe the modes; they do not copy the rule 15 table of the
  test-mode spec
- tests in `test/unit/setup-choices.test.mjs`, named with the scenario id: AC-06 over the whole `QUESTIONS` list
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api` after changing `kit/`

## Out of scope

- the skill and docs (T-M2-15)

## Done when

- `npm run spec:matrix -- --check`
- `node tools/saf/bin/saf.mjs choices --group 6 --lang th`
- `node tools/saf/bin/saf.mjs choices --group flow --lang en`
- `npm test`
- `npm run docs:check`
