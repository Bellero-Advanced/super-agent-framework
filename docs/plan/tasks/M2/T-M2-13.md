# T-M2-13 — saf choices --group explains each option for groups 1–4, en and th

## Why

Today the interview offers "light · standard · strict" or "Max · Balanced · Economy" with one recommendation and no
reason. People should see what each option costs and when to pick it, in their own language —
[spec rules 4–8, 12, 14–15](../../../specs/setup-choices.md#the-data-table).

## What to do

- `choices.mjs` — `CHOICES` entries for every `choice` and `value` question of groups 1–4 (language and people ·
  project · stack · models): per entry the covered option values and `what` · `good` · `cost` · `when` in `en` and `th`
  next to each other (one row per language keeps the table flat). Options SAF treats the same share one entry (every
  Node package manager · every database other than `none`). Write about what the option changes **in SAF** (rule
  templates, recommended roles and packs, card caps, models, command syntax), not general product advice. No numbers
  or model ids in the text (rule 8)
- `FIELD_MAX` — the per-field length limit (keep a field to one short sentence)
- `groupText(group, lang)` — the rule 12 output; append the derived values for `project.rigor` (from `RIGOR`) and
  `models.preset` (from `MODEL_PRESETS`)
- `bin/saf.mjs`: `choices --group <1-8|flow> [--lang en|th]`; usage errors as in rule 15
- tests in `test/unit/setup-choices.test.mjs`, named with the scenario ids: AC-04 through the CLI; AC-05 over every
  entry present (shape, length, no two adjacent digits, no `claude-`, every value of a question with entries covered
  exactly once)
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api` after changing `kit/`

## Out of scope

- groups 5–8 and `flow` (T-M2-14) · the skill does not call the command yet (T-M2-15)

## Done when

- `npm run spec:matrix -- --check`
- `node tools/saf/bin/saf.mjs choices --group 2 --lang th`
- `node tools/saf/bin/saf.mjs choices --group 4 --lang en`
- `npm test`
- `npm run docs:check`
