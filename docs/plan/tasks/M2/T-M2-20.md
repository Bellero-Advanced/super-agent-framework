# T-M2-20 — A setup re-run keeps your edited living files and leaves package.json alone

## Why

Re-running `/saf-setup` to change one setting today archives an edited `docs/DECISIONS.md` and an active `M1.md` and
writes the template draft back (M1 returns to `planned`), and it re-formats `package.json` even when no script is
missing (reproduced on a temp project). The team loses its working plan from the active files.
[Spec rules 1–5, 7, 9–10](../../../specs/setup-rerun.md#2-rules).

## What to do

- `kit/tools-saf/lib/generate.mjs`:
  - `LIVING_FILES` data table (path patterns: `docs/DECISIONS.md`, `docs/INDEX.md`, `docs/plan/milestones/`,
    `docs/plan/tasks/`)
  - in the rendered-file loop of `generate()`: on a re-run (`rerun`), an existing living file that differs and is not
    `ownedUnchanged` is not archived and not written; copy its old manifest entry (if any) into `next.files`; push it
    to `report.kept` and push a warning `<path> has your edits — kept, the new settings did not reach it` (warnings
    are already printed by `setup` and `init`, so no CLI change)
  - export one pure function for the script merge (for example `mergeScriptsText(text, want)` → new text or `null`
    when nothing is added, plus `added` · `kept` · an error flag for invalid JSON / non-object root), moved from
    `mergeUpgradeScripts` in `src/install.mjs` (BOM, indentation, line endings, trailing newline);
    `mergePackageJson` uses it and writes only when a script was added — it still creates `package.json` when missing
- `src/install.mjs`: `mergeUpgradeScripts` calls the shared function; its log lines and `scripts: { added, kept }`
  result stay the same (UPG-AC-01 … 06 must still pass unchanged)
- `docs/upgrade.md` re-run paragraph and the "Re-running" section of `kit/claude/skills/saf-setup/SKILL.md`: one
  sentence each — edited decision log, index, milestone and card files are kept on a re-run; other edited files are
  archived then replaced (T-M2-22 adds the dry run to both)
- `test/unit/setup-rerun.test.mjs`: temp projects via `generate` / `init`; one test per scenario id in its name
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then
  `git checkout -- examples/todo-api/.claude examples/todo-api/package.json` (the stale example skill copy is review
  note C, batched — not this card)
