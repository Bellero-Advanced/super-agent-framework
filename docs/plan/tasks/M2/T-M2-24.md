# T-M2-24 — /saf-setup asks for skill packs and installs only after an explicit yes

## Why

"Picked in setup" must not mean "trusted by default": the interview shows the full `pack show` output and asks a yes/no
question with no recommended answer. **Security-relevant:** review the skill wording with the `security-review` skill.
[Spec rule 13](../../../specs/skill-packs.md#interview).

## What to do

- `kit/tools-saf/lib/choices.mjs`: move `skills.external` from `NOT_ASKED` to a group-5 `value` question
  (`skill-packs-external`) with one explanation in en and th (what · good for · cost — agents follow its text · pick
  it when you or your team wrote or reviewed the pack)
- `questions.md`: a group-5 row with Key `skills.external`, default "none"
- `SKILL.md` group 5: for each path the person gives, run `node tools/saf/bin/saf.mjs pack show <path>`, show the output
  as printed, say in one line that a skill is instructions agents will follow, ask "Install this pack?" Yes · No with
  no "(recommended)"; yes → add `{ path, sha256 }` as printed to the answers; exit 1 → show the problems and do not offer
  install
- `docs/setup-questions.md`: one sentence about the question and `pack show`
- `test/unit/skill-packs-setup.test.mjs`: one test named with `PACK-AC-07`; SETUP-AC-01/02/05/06 must stay green
- run `npm run saf:refresh`

## Out of scope

- engine install logic (T-M2-23) · fetching by URL
