# T-M2-28 — Setup explanations match the code

## Why

The `/saf-setup` explanations are what a person decides by, and some of them are wrong
([spec rules 24–25](../../../specs/setup-choices.md#explanations-match-the-code)). The spec reviews of T-M2-12 and
T-M2-13 found them. Owner order 2026-11-24: fix them before the M2 exit gate. The notes are in
[M2-review-notes.md](../../notes/M2-review-notes.md): 13/4 · 13/7 (wrong text) and 13/5 · 13/6 · 13/8 · 13/9 · 12/2 ·
12/4 (missing or vague text, same file).

## What to do

Edit `kit/tools-saf/lib/choices.mjs` only, en and th. Check every sentence you write against the code named here. Each
field stays within `FIELD_MAX` (160, do not raise it). No run of two digits, no `claude-`.

- **13/4** `project-type` `api` `what`/`cost`: it adds the server rule. It also adds the UI rule when translation is
  required (`ruleSet` in `generate.mjs`, the `ui` line ORs `config.people.i18nRequired`). Drop "only".
- **13/5** `ui-languages` `several`: it adds the UI rule for every project type, including types with no UI rule of
  their own (api, data-ai, library-cli, other). The interview then suggests the content-writer role and the i18n pack
  (`questions.md` group 7 defaults).
- **13/8** `ui-languages` `one none` `cost`: even without translation, the UI rule (for types that have it) keeps
  user-facing text in one place (`templates/rules/ui.md`, the `{{else}}` branch). So adding a language later means
  adding keys, not hunting for strings. Say only what is true for both `one` and `none`.
- **13/7** `custom-models` (`resolveConfig` uses `||=`, `roleTable` in `config.mjs`):
  - a set id wins over **any** preset. An empty id falls back to the preset's model, and to Balanced's model for
    Custom (the `else` branch)
  - planner-tier roles get the planner id: the `tier: "planner"` roles of `ROLE_LIBRARY`, plus custom roles marked
    planner. Every other role gets the builder id
  - `models.overrides` beats both for a single role
  - do not list the planner roles by name unless the list matches `ROLE_LIBRARY`. Change the `when` field so it no
    longer says "only with Custom"
- **13/6** `project-rigor` `strict`: the interview suggests the security-auditor role (planner tier, the costlier
  model). The generated Definition of done requires a security-auditor review of each milestone even when that role
  is not enabled (`reviewSecurity` in `generate.mjs`, CLAUDE template line "security-auditor reviewed the milestone").
  Put this in `cost`/`when` so the person knows to enable it.
- **13/9** rigor line appended by `choices --group 2` (`RENDER["project-rigor"]` + `LABELS`):
  - the size labels name their unit: changed code lines and changed test lines
  - the review value prints as words in the chosen language (a small en/th table keyed by the `workflow.review` enum
    values, inside `LABELS` or next to it), not `m-cards` / `every-card+security`
  - merge-check kinds stay as they are (they are command names)
- **12/2** `NOT_ASKED["workflow.measure.waitMs"]`: interpolate `EXIT_BUSY` from `measure.mjs` in en and th instead of
  the literal exit code.
- **12/4** `NOT_ASKED` `models.overrides` and `workflow.review`: say that the change reaches the generated agent files
  and docs only after setup runs again (re-run `/saf-setup`).
- `test/unit/setup-choices.test.mjs`: update only the SETUP-AC-04 rigor-line assertion to the new labels and review
  words. SETUP-AC-05 and SETUP-AC-06 must pass unchanged.
- `test/unit/setup-choices-facts.test.mjs`: SETUP-AC-11 (id in the test name). It renders with `generate` into temp
  folders:
  - assert the code facts first (UI rule present / absent, role models, the strict CLAUDE.md line)
  - then assert the explanations name them. Prefer tokens that are the same in en and th (`content-writer`,
    `security-auditor`, `models.overrides`, `i18n`), plus "UI rule" for en
  - include one negative fact: `api` without i18n has no UI rule
- run `npm run saf:refresh` and `node bin/cli.mjs upgrade --dir examples/todo-api`, then restore
  `examples/todo-api/.claude` and `examples/todo-api/package.json`
